## 작업 순서

1. `$ARGUMENTS`로 전달된 요청 내용을 읽는다 (텍스트, 이슈 설명, 스펙 등).
2. 관련 영역의 `CLAUDE.md`를 확인해서 기존 컨벤션과 구조에 맞는지 검토한다.
3. 바로 코드를 작성하지 않고, 먼저 아래 형식으로 계획을 제시한다:

```markdown
## 요청 요약

(요청을 1~2문장으로 재정리 - 이해가 맞는지 확인 목적)

## 영향 범위

- 관련 파일/도메인
- 프론트/백엔드 중 어디를 건드리는지
- DB 스키마 변경이 필요한지

## 구현 방향

(단계별로 무엇을 어떻게 할지)

## 확인이 필요한 부분

(모호하거나 여러 방향이 가능한 지점)
```

1. 사용자가 계획에 동의하면 그때 실제 구현을 진행한다. 모호한 요청은 추측해서 구현하지 말고 확인이 필요한 부분에 명시한다.

인자: $ARGUMENTS (요청 내용 전체)
